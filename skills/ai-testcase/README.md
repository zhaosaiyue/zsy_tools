# AI测试用例生成器

AI 驱动的测试用例生成器。深度解析需求/技术/核心用例文档，智能选择黑盒测试方法，生成 Markdown 结构化测试用例。

---

## 快速上手

**第一步：在对话中说出需求**

推荐直接 @ 相关文档：
```
@需求文档.pdf @技术文档.pdf 使用skill生成用例
```

或直接 @ 文档：

```
帮我生成测试用例
```

**第二步：提供文档路径**

可同时提供多份需求文档、技术文档和已有核心用例，也可以提供目录或 glob。未指定输出目录时：所有源文档同目录则输出到该目录，否则输出到当前工作目录。

**第三步：确认模块列表**

AI 解析完文档后输出识别到的模块，确认无误输入 `确认`，或直接输入 `直接出` 全自动跑完。

**完成后产出 Markdown 文件：**
- `2026-04-22_14-30-00_需求名.md` — 可直接阅读、评审和归档

## 快捷指令

| 指令 | 效果 |
|------|------|
| `直接出` / `全自动` | 跳过所有确认节点，一气呵成 |
| `深度出` | 每模块生成前展示逻辑骨架供 review，自审追加幂等/反向/外部依赖失败场景 |
| `只要核心` | 只生成主流程用例，跳过字段级校验 |
| `重新解析` | 强制重新读取文档 |

## 工作流程

```
阶段 0：信息收集
  └─ 收集 0..N 份需求/技术/核心用例文档、输出目录、测试范围
  └─ 完整读取所有文档并建立模块与来源映射
  └─ PDF 分页读取，并检查文字、嵌入图片和矢量图表

阶段 1：测试分析
  └─ 按模块判断需求类型（后端逻辑/配置/数据/前端/集成）
  └─ 按需生成判定表（条件维度 ≥ 3 时触发）

阶段 2：流式生成 & 写入
  └─ 逐模块生成，每模块完成立即写入 .md，支持断点续写
  └─ 仅根据文档明确的跨系统关系生成全链路场景
  └─ 文件末尾只生成一次精简回归节点
```

## 核心原则

- **反幻觉**：所有内容必须来源于文档，不凭空推断
- **原子性**：每条用例只验证一个行为
- **场景明确**：后端用例写清前置状态、触发条件和关键参数
- **前端按需**：只有前端模块才展开操作路径和交互
- **可验证**：预期结果为系统具体反应（错误码、UI 文案、页面跳转）

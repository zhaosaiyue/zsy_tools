# 测试文档

把已经确认的测试用例整理为轻量、可执行、便于协作和上线决策的测试文档。

## 固定母版

- 飞书模板：`https://beike.feishu.cn/wiki/CgxZwD88PipVsska4HFct6GCnGc`
- 始终复制母版后编辑副本，禁止直接修改母版。
- 保留母版中的表格、多维表格和其他资源块；仅在用户明确要求时删除。
- 模板结构发生变化时，以实时读取的母版为准，不依赖记忆中的 block ID 或旧版正文。

## 命名规则

统一使用：

`yyyyMMdd 需求简称`

- 日期采用文档创建当天的北京时间；用户明确指定命名日期时使用指定日期。
- 日期与需求简称之间只保留一个半角空格。
- 需求简称从用户提供的需求名称中提炼，保持简短且能区分业务范围。
- 保留业务缩写原有大小写，如 `bsu`、`BSU`、`ToB`。
- 需要区分子项目时使用短横线，例如 `20260407 北京大租赁融合-财务`。
- 不追加“测试文档”“测试方案”“测试报告”等固定后缀。
- 需求名称已经带有同格式日期前缀时不重复添加日期。

示例：

- `20260306 确品下单业绩计算场景迭代`
- `20260422 bsu规则配置`
- `20260604 BSU软电-计入节点下沉到s单`

## 用例边界

只使用用户明确表示已经评审完成、质量确认无误的测试用例：

- 按用例原有的模块、分类、场景和预期结果映射到测试文档。
- 复用用例中的测试范围、回归、明确记录的未决问题和实现风险，不重新扩写或删减独立业务分支。
- 不擅自修改已确认用例的业务预期；发现材料冲突时只记录能够从材料中明确描述的冲突事实。
- 不生成、补充、优化或评审测试用例，也不自动调用其他用例生成流程。
- 用例尚未确认时停止生成测试文档，提示用户先完成用例确认。

## 输入识别

优先识别：

- 已确认测试用例文件或目录
- 需求、技术方案、接口文档、Showcase 等材料
- 被测平台、服务、版本或分支
- 测试环境与测试数据说明
- 目标目录：飞书 Wiki 节点、飞书云盘文件夹或本地目录
- 可选的测试排期、负责人和上线时间

用户已提供路径、链接和范围时直接执行，不重复询问。缺少测试用例或目标目录且无法从当前上下文唯一确定时才询问。

### 用例发现

1. 用户给出用例文件时直接使用。
2. 用户给出目录时，递归查找内容属于本需求的测试用例文件；支持 Markdown、表格、飞书文档及其他当前环境可读取的格式。
3. 当前对话已明确确认某份用例时优先使用该文件。
4. 不得仅凭修改时间从多个不同需求的文件中猜选；候选不唯一时列出候选并请用户指定。
5. 完整读取选中的用例到 EOF，并读取生成用例时引用的必要材料。

## 目标分流

### 飞书 Wiki 目录

1. 读取并遵循 `lark-shared`、`lark-wiki` 和 `lark-doc` skill。
2. 解析目标 Wiki URL，确认目标空间和父节点。
3. 先检查目标父节点下是否已有同名文档。存在同名文档且用户未明确要求更新时，先确认，禁止重复创建。
4. 使用 Wiki 节点复制能力把固定母版复制到目标父节点。
5. 按命名规则设置副本标题，再读取副本的完整结构和 block ID 后精准填充。

### 飞书云盘目录

1. 读取并遵循 `lark-shared`、`lark-drive`、`lark-wiki` 和 `lark-doc` skill。
2. 优先使用官方复制能力保留母版结构和资源块。
3. 若 Wiki 母版无法直接复制到目标目录，读取母版后创建普通飞书文档；明确说明嵌入式资源块的降级情况，禁止伪造不可重建的 token。

### 本地目录

1. 确认目录存在且可写。
2. 输出 `yyyyMMdd 需求简称.md`，结构与下文一致。
3. 同名文件存在时，只有用户明确要求覆盖或更新才修改；否则先确认。
4. 目录中只新增或修改最终交付文件，不保留临时文件。

## 内容生成

保持敏捷、简洁和事实驱动。不要加入厚重的审批、签字、通用术语解释或与本次迭代无关的测试方法介绍。

只写材料中明确存在的信息。某个字段、表格行或章节没有材料支撑时，留空或删除对应占位内容；不要写“待确认”“不涉及”“暂无”“未提供”等占位文字，也不要在正文或交付说明中罗列缺失信息。

### 一、项目背景

用 1～3 个短段落说明：

- 本次迭代解决的问题和业务目标
- 主要变更及受影响模块
- 本次测试范围与明确不覆盖内容

不复制整篇 PRD，不把代码实现细节当成业务背景。

### 二、测试数据

#### 2.1 涉及平台、文档

填入实际存在的内容：

- 被测平台、服务或项目
- PRD
- 技术文档或接口文档
- Showcase
- 已确认测试用例

使用可点击链接或绝对文件路径。没有某类材料时删除对应占位行，不保留 `xxxx`、空链接、说明性占位文字或虚构地址。

#### 2.2 测试环境

记录执行测试所需的最少信息：

- 环境、域名或集群
- 应用/服务版本、分支或构建号
- 关键配置、开关和外部依赖
- 特殊账号、权限或终端要求

材料没有提供的信息保持为空或删除对应占位块，不猜测、不提示。

### 三、测试物料

只列实际需要准备的数据和账号。每项写清：

- 数据类型或业务对象
- 关键前置状态和影响分支的字段值
- 造数入口或准备方式
- 可复用标识、查询位置或核对方式

测试用例中多个场景共用同一批数据时合并描述；不同时间来源、角色、枚举或落库路径需要独立造数时分别列出。

### 四、测试场景

以已确认用例为唯一覆盖基线：

1. 按用例的模块和分类组织场景。
2. 每个独立场景至少映射到表格中的一行；不得因结果相似丢失不同的数据准备、触发入口或判断分支。
3. “测试模块”填写模块名称；“测试场景”填写前置状态、触发条件、关键输入和简明预期；没有执行结果时“测试结果”保持为空。
4. 用户提供执行结果时，更新为“通过 / 失败 / 阻塞 / 不执行”，并附缺陷或证据链接。
5. 用例很多时允许按模块拆成多张表，但不以概述替代已确认场景。
6. 用例中明确记录的未决问题不写成确定场景；只有内容具体且会影响测试或上线时才写入风险点。
7. `回归` 场景在表格中标明“回归”，不重复复制同一场景。

### 五、风险点

只记录会影响测试或上线判断的内容：

- 用例中明确记录的未决问题和当前实现风险
- 外部依赖、环境、数据、权限或排期阻塞
- 未覆盖范围及其影响
- 已知缺陷、临时绕行方案和上线后观察项

每项包含“风险、影响、应对或待决策人”。没有事实依据时不要填通用风险套话。

### 六、测试与上线排期

- 用户提供节点、任务、日期和负责人时，填入母版现有排期多维表格。
- 编辑嵌入式多维表格前读取并遵循 `lark-base` skill。
- 用户未提供排期时不填写表格，不编造日期和负责人。

### 七、测试结论

仅在用户提供了执行结果时，在排期之后追加一个简短章节并汇总：

- 已执行、通过、失败、阻塞和未执行数量
- 未关闭缺陷及影响
- 未覆盖项和残余风险
- 结论：建议上线 / 有条件上线 / 不建议上线
- 上线后的冒烟、监控和回滚关注点

仅在执行数据足以支撑结论时给出上线建议；否则不写测试结论。

## 飞书编辑规则

1. 先复制，再读取副本 `full` 内容；不要复用母版的 block ID。
2. 优先用 `str_replace` 或 `block_replace` 精准替换占位内容。
3. 需要扩展测试场景表时，重建副本中的场景表或按模块插入新表；不要覆盖整篇文档。
4. 任何写操作后根据 `lark-doc` 的 block ID 生命周期规则重新读取必要章节。
5. 原样保留 `<bitable>`、`<sheet>`、`<img>`、`<source>`、`<whiteboard>`、引用和人员组件的 token。
6. 禁止用 `overwrite` 重建含资源块的副本，除非用户明确接受资源丢失。

## 执行流程

1. 展开输入路径和链接，列出简短材料清单。
2. 完整读取已确认用例及必要材料，提取需求名称、模块、场景、范围、回归、明确未决问题和风险。
3. 按命名规则生成标题，解析目标目录并检查同名文档。
4. 复制飞书母版或创建本地 Markdown 文件。
5. 按章节顺序填充背景、材料、环境、物料、场景、风险、排期和结论。
6. 重新读取最终文档，核对结构、场景数量、链接、占位符和资源块。
7. 修正发现的问题后交付。

## 自检

交付前确认：

- 母版未被修改，目标文档位于用户指定目录。
- 文档标题符合 `yyyyMMdd 需求简称`，没有添加固定后缀。
- 使用的是用户确认的用例，没有重新解释或删减独立业务分支。
- 每个独立用例场景都有对应测试场景，或有明确的排除原因。
- 需求、技术文档和用例链接可识别；没有遗留 `xxxx`、空白占位行或伪造链接。
- 环境、数据、排期和负责人没有凭空补全。
- 材料未提供的字段、表格行和章节没有填入任何占位文字。
- 风险与本次迭代直接相关，测试结论与当前执行数据一致。
- 飞书资源块和 token 保持完整。
- 本地目标目录只包含最终交付文件。

交付时说明文档位置、覆盖模块数、场景数和风险数。
